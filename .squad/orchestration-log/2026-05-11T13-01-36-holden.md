## Work Completed

Holden analyzed the existing `server.py` and infrastructure to produce a comprehensive investigation plan for eliminating the OAuthProxy layer via the "direct-Entra" pattern.

### Key Findings

1. **Root cause (revised):** VS Code's client ID (`aebc6443-996d-45c2-90f0-388ff96faa56`) must be in `preAuthorizedApplications` on the resource app registration. Currently missing; this is why Entra returns `AADSTS65002` when VS Code (a Microsoft first-party client) requests a custom API scope.

2. **VS Code MCP OAuth behavior:** Tyler Leonhardt (vscode#254009) confirmed VS Code strips the `resource` parameter from `/authorize` requests before sending to Entra. This enables direct Entra flows (no proxy needed) if pre-auth is in place.

3. **Architectural shift:** Current OAuthProxy pattern (PKCE via proxy, then proxy→Entra). Proposed: FastMCP with `AuthSettings` + `JWTVerifier` (PKCE directly to Entra).
