### Key Findings

1. **H2 CONFIRMED (HIGH):** VS Code and AI Foundry do NOT invoke the MCP server's /token endpoint
   - VS Code uses `IAuthenticationService` with `https://vscode.dev/redirect`
   - AI Foundry uses OAuth passthrough (server-side token relay) with `https://foundry.azure.com/`
   - Both present Bearer tokens issued directly by Entra ID; they never use the proxy-AS pattern

2. **Architectural Mismatch:** The intel `cloud-helper-mcp` acts as an Authorization Server (AS), but VS Code/Foundry are designed as Resource Server (RS) clients
   - onsemi reference implementation uses APIM + PRM (RFC 9728) — MCP server validates Bearer tokens, doesn't issue them
   - Working pattern: Client → Entra (token) → MCP server (validates)
   - Current intel pattern: Client → MCP server (issues token) — clients never reach this step

3. **Recommended Fix:** Switch from AS-mode to RS-mode per RFC 9728
   - Remove proxy /authorize and /token endpoints
   - Add `/.well-known/oauth-protected-resource` pointing to Entra as AS
   - Validate incoming Bearer tokens using JWT validation middleware
