Monica synthesized the merill/mcp-entra-design documentation (docs 02, 06, 14, 15) into a comprehensive, actionable checklist for implementing the "Direct Entra" MCP pattern.

### Key Findings

1. **Architecture clarity:** "Direct Entra" is NOT a proxy pattern—it's RFC 9728 Protected Resource Metadata (PRM) + EasyAuth v2 configuration on the resource server. Entra points directly to the MCP server.

2. **MCP discovery flow:**
   - Client hits `/mcp/` → 401 + `WWW-Authenticate: Bearer resource_metadata="<PRM_URL>"`
   - Client fetches PRM → learns authorization servers and scopes
   - Client fetches Entra OIDC metadata → gets endpoints
   - Client initiates PKCE flow scoped to the API

3. **Critical "2 Places" pattern:** VS Code client ID must be registered in:
   - **Place 1:** Entra app registration's `preAuthorizedApplications`
   - **Place 2:** EasyAuth's "Allowed client applications"

4. **4 Implementation parts:**
   - Part 1: Entra app registration setup
   - Part 2: EasyAuth v2 configuration
   - Part 3: PRM enablement
   - Part 4: VS Code client config (no changes needed)

### Pitfalls Documented

- **Pitfall #1:** EasyAuth v1 does NOT enforce auth properly—must use `~2`
- **Pitfall #2:** Redirect to login breaks non-browser clients—must return 401
- **Pitfall #3:** App Service restart delay (several minutes)
- **Pitfall #4:** VS Code pre-auth in two places (the most common mistake)
